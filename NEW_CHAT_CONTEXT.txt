TurboBoost / Foreign Unlock policy
- retainedFamilies is EMPTY.
- ser8989-turbohack and all other known unlock families are Foreign.
- Confirmed Foreign modules may be removed directly WITHOUT a clean baseline.
- GUID/name/single string alone never authorizes mutation.
- Exact source-bound FFS is re-authorized immediately before mutation.
- Unclassified/heuristic candidates are NEVER auto-modified.
- No bulk Foreign removal.
- Direct removal is exact PI FFS state transition DataValid -> Deleted, normally one state byte only.
- CPU Patch is CPUID 0x000306F2 + Platform Flags 0x6F; Foreign cleanup must not restore/remove it.
- RestoreBaselineFfs remains a separate blocked/future path.

UEFI driver update architecture
- UI shows total detected UEFI driver inventory separately from the smaller verified update/restriction catalog.
- Ready + CanApply gets an Update button; UpToDate shows Current; blocked/review-only remains non-executable.
- No bulk update and no blind update by GUID.
- Exact SHA -> SHA transitions are data-driven in x99-driver-updates.json.
- Managed physical strategies:
  InPlace
  GrowIntoAdjacentFreeSpace
  RebuildFirmwareVolume
  RequiresRebase
  Unsupported
- FV rebuild keeps the same FV bounds/length and preserves unrelated content.
- Strict PE32/PE32+ XIP rebasing is supported only for provable pure PEIM cases with valid relocations.
- TE, SEC/PEI Core, combined PEIM/DXE, compressed/guided/ambiguous PEI, fixed/VTF/unknown movement remain fail-closed.
- Intel RST/RSTe exact transitions are implemented; RSTe 4.6.0.1018 -> 5.5.5.1005 is AutomaticManaged when the physical planner proves it safe.
- Intel LAN/NVMe/Realtek/Marvell/ASMedia etc. must not be auto-updated without exact compatibility authorization.
