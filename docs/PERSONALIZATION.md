# Персонализация BIOS

Раздел **Персонализация** изменяет только рабочую копию открытого BIOS. Исходный файл не перезаписывается.

## Стартовые изображения

Для поддерживаемой AMI X99-разметки приложение ищет два известных logo FFS: большой boot logo и малый AMI logo. Замена разрешена только BMP `BI_RGB` с теми же шириной, высотой, ориентацией, глубиной цвета и внутренней BMP-разметкой, что у текущего изображения. После пересборки AMI LZMA FFS BIOS повторно анализируется; второе logo и состояние Beeper должны сохраниться.

Персонализация не перемещает соседние FFS-файлы. LZMA-поток детерминированно перепаковывается допустимыми вариантами `NumFastBytes` в исходном AMI-формате без EOS. Если новый FFS становится меньше ровно настолько, что его естественное 8-байтовое выравнивание перенесло бы следующий FFS назад, редактор сохраняет исходную границу allocation добавлением внутри целевого FFS отдельной стандартной RAW padding-секции с маркером `XV3P`. Такая секция распознаётся и заменяется при следующей модификации; в LZMA-поток мусор не добавляется и соседние FFS не перемещаются. Если новый LZMA-поток физически больше исходного allocation, операция блокируется как нехватка безопасного места вместо перестройки всего firmware volume.

## Beeper

Опция отключает только распознанную функцию AMI BDS `ConInAvailabilityBeep`. Поиск выполняется структурно по PE-таблицам/строкам/ссылкам и проверяемым данным, без фиксированного смещения. Для плотно упакованного BDS редактор сначала ищет внутри того же исполняемого PE уже существующий листовой `return EFI_SUCCESS` (`xor/sub eax,eax; ret`) и заменяет первые пять байтов `ConInAvailabilityBeep` на относительный `jmp` к такому коду. Это не добавляет исполняемый код и не меняет соседние FFS, а несколько безопасных trampoline-вариантов дают LZMA-кодеру возможность сохранить исходный allocation. Старый inline-вариант `xor eax,eax; ret` остаётся распознаваемым для обратной совместимости. При включении исходный RIP-relative `lea` восстанавливается структурно по уникальному `ConsoleInDevicesStartedProtocol` GUID, поэтому восстановление не зависит от фиксированных байтов displacement. POST/PEI/DXE диагностические beep-коды не отключаются.

Любая неоднозначная или неизвестная структура блокирует автоматическую модификацию (`fail-closed`).
